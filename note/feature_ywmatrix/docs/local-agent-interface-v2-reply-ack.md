## 二、一个遗留项，需要你们确认

**同一个 `session_id` 必须始终路由回同一台机器的同一个工作目录。**

这是我们上次提的三条要求里唯一没被回复涉及的一条。ywcoder 的会话文件是**按工作目录分桶存**的（`<项目目录派生路径>/<session_id>.jsonl`）。你们把 `session_id` 落库、用户隔天回来继续聊时，如果这个任务被调度到**另一台机器**、或同一台机器的**另一个 workdir**，我们查不到该会话文件，就会**静默地当成新会话创建**——表现是：不报错、不失败，但用户的历史上下文凭空消失（"聊着聊着失忆"）。

如果你们目前是单机单目录部署，这条暂时不会触发；但只要将来做多 agent 调度或允许切换工作目录，就需要在网关侧保证 `session_id → (agent, workdir)` 的绑定。想确认一下你们的调度模型是否已经保证了这点。

## 三、一处小笔误，建议修一下

回复里 ④ 的链路写成「网关透传给 client → adapter → shim → ywcoder `--resume <uuid>`」。实际要分两种：

- 该会话**本地尚不存在**（新会话）→ 必须用 `--session-id <uuid>`；对不存在的会话用 `--resume` 会被 ywcoder 直接拒绝并退出。
- 该会话**本地已存在**（续接）→ 才用 `--resume <uuid>`。

这个分支由 shim 内部判断，不需要你们感知，接口也不受影响。只是如果这句话进了正式文档，将来排查问题时容易误导人，建议改成「shim 据本地会话是否存在，选用 `--session-id` 或 `--resume`」。
