# 给领导的品牌迁移汇报框架

> **可直接复制使用的精简说明**
>
> 本次 YwCoder 品牌迁移不是简单的“把 Claude Code 改成 YwCoder”，而是在**不破坏存量用户配置、登录态、skill 功能**的前提下，把整套产品身份体系从 OpenClaude/Claude Code 迁到 YwCoder。目前已改 250+ 文件，599 个测试全绿，版本升至 v1.2.0；仍剩少量文案残留、GitHub Models 环境变量联动、skill 权限沙箱双前缀兼容，以及真机验证 + 内网发布工作。

---

## 一、一句话定位

这不是品牌文案替换，而是**在保持现有用户不丢配置、不丢登录态、skill 不失效的前提下，把整套产品身份体系从 OpenClaude/Claude Code 迁到 YwCoder**。

---

## 二、为什么“看起来简单”

领导觉得简单，通常只看到一层：

| 表面看 | 实际做 |
|---|---|
| 把 `Claude Code` 改成 `YwCoder` | 要区分 **用户可见文案 / 模型名 / SDK 符号 / 外部 URL / 环境变量 / 文件路径** 六类，每类处理规则不同 |
| 改个命令名 `claude` → `ywcoder` | 涉及 shell 补全、VS Code 扩展、bin 入口、profile 文件名、provider 描述等 14 处联动 |
| 配置目录改个名 | 涉及 `.claude/` → `.ywcoder/` copy-keep 迁移、worktree 跳过、`.gitignore` 同步、settings 缓存失效、权限沙箱路径匹配 |

## 三、工作量拆解（有据可查）

### 1. 阶段跨度

文档显示从 2026-04-23（profile 文件名改造）到 2026-06-14（第一轮审查），**持续近两个月**，分 A/B/C/D 多阶段推进。

### 2. 改动规模

- 源码文件：**250+**
- 单测：当前 **599 pass**（clean env）
- 环境变量 fallback：**46+ 个** `YWCODER_*` 变量，同时保留旧 `CLAUDE_CODE_*`
- 构建产物：每次改完必须 `bun run build` 后重新扫 `dist/cli.mjs` 验收（不是源码改了就算）

### 3. 关键模块

| 模块 | 代表工作 |
|---|---|
| 命令/入口 | `ywcoder` 替代 `claude`，bin 入口、VS Code 扩展默认值 |
| UI 文案 | REPL、Logo、TrustDialog、Tips、Feedback、Marketplace 通知等 |
| 配置体系 | HOME 级 `~/.ywcoder`、项目级 `.ywcoder/`、settings sync key |
| Auth | `~/.ywcoder/.config.json` 新装默认，存量 `~/.claude.json` fallback |
| 权限沙箱 | `/.claude/skills/` 路径前缀不能单改字符串，否则存量 skill 静默失效 |
| Provider/GitHub Models | `CLAUDE_CODE_USE_GITHUB` 提示要联动写入/读取逻辑一起改 |
| 构建 infra | 顺手修了 Bun macro feature flag 静默失效的底层 bug |

## 四、复杂度来源（重点讲给领导听）

### 1. 验收标准不是源码，是构建产物

`START_HERE.md` 明确原则：**“暴露面 = 字符串字面量，以扫 dist 为准”**。很多字符串在源码里藏得深（JSDoc、schema 描述、error message、LLM prompt），必须 build 之后才能发现。

第一轮审查就是在文档说“D7 已完成”之后，又扫出 **14 处活跃用户面残留**，其中 8 处已修复，6 处仍待处理。

### 2. 向后兼容是硬约束

- 存量用户 `~/.claude.json` 不能丢登录态
- 存量项目 `.claude/` 目录 copy-keep，不能删
- 存量 skill 沙箱路径要**同时认 `.claude/skills/` 和 `.ywcoder/skills/`**
- 旧环境变量 `CLAUDE_CODE_*` 必须继续可读

这导致“改个路径”往往要加 fallback 分支，代码量翻倍。

### 3. 有些文案不能单独改

比如 `CLAUDE_CODE_USE_GITHUB=1` 的提示，底层写入和读取都还用旧变量名。单独改提示会**误导用户**，必须先改 provider 读取逻辑，再改文案。

### 4. 品牌保留项需要人工裁决

模型名（`claude-sonnet-4-6`）、SDK 导入（`@anthropic-ai/sdk`）、API 密钥变量（`ANTHROPIC_*`）、外部链接（`claude.ai`）等**必须保留**。每处都要判断“能不能把 Claude 换成 YwCoder 而语义正确”。

## 六、给领导的建议话术

如果想让领导理解“为什么花了这么久”，可以这样说：

> 这次品牌迁移的表面工作（改文案、改命令名）确实不大，但核心难点在于 **“不破坏存量用户”**。用户的配置文件、登录态、项目级 settings、skill 权限沙箱、环境变量脚本都不能因为改名而失效。
>
> 所以每处改动都要回答三个问题：新用户怎么走？老用户怎么 fallback？构建产物里还有没有残留？这导致实际工作量远超一次性字符串替换，目前源码改了 250+ 文件，测试 599 个，还需要两轮扫描 + 真机验证才能进 main。
