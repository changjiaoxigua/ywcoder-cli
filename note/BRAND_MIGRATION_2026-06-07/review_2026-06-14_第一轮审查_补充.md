## 一、扫描方法与口径

1. 使用 `grep -rn 'code\.claude\.com' src` 全量扫描源码。
2. 同步扫描 `dist/cli.mjs` 与 `dist/cli.mjs.map`，确认源码残留会原样进入构建产物。
3. 按**用户是否可能实际看到**分为「活跃面 / 已禁用面 / 内部模板 / 测试期望」四类。
4. 同时检查 `PRODUCT_URL`（`https://claude.com/claude-code`），该常量虽不命中 `code.claude.com` 正则，但同属于用户可感知品牌 URL，一并纳入。

## 五、dist 构建产物验证

`dist/cli.mjs` 中 `code.claude.com` 共命中 **约 30 处**，与源码残留一一对应，说明：

- 活跃面源码修改会直接进入产物。
- 已禁用功能由于代码仍在包中，字符串也会进产物（但不影响运行时可达性）。
- 验收应以 **运行时可达路径** 为准，而非单纯统计 dist 命中数。

`dist/cli.mjs.map` 中也有大量命中，仅 source map 用途，不影响用户。

## 六、处理建议：去链接化（不引入新外链）

当前内网既无 GitHub 仓库也无独立文档站，因此**不宜把链接替换为任何新 URL**（会出现 404 或指向不可达服务）。建议方案：

### 6.1 活跃用户面：注释原 URL/Link 代码，替换为中文文案

示例：

```tsx
// 改前
<Text>For more help: <Link url="https://code.claude.com/docs/en/overview" /></Text>

// 改后：注释原代码并替换为无链接中文文案
// <Text>For more help: <Link url="https://code.claude.com/docs/en/overview" /></Text>
<Text>寻求更多帮助：请联系运维支持部</Text>
```

覆盖范围：第 2.1、2.2 节所有条目。

### 6.2 Settings 校验提示：注释 `docLink` 与基地址

`src/utils/settings/validationTips.ts` 中：

- 注释掉 `DOCUMENTATION_BASE` 常量。
- 注释掉所有 `tip.docLink` 赋值。
- 注释掉 `PATH_DOC_LINKS` 对象及相关引用。
- 保留 `suggestion` 文本，功能不变。

### 6.3 Keybindings 模板：注释 `$docs` 字段

`src/keybindings/template.ts` 与 `src/skills/bundled/keybindings.ts` 中注释掉 `$docs` 键。该字段非功能必填。

### 6.4 PRODUCT_URL：注释 `websiteUrl` 字段

在 `src/services/mcp/client.ts` 两处 `new Client({...})` 中注释掉 `websiteUrl: PRODUCT_URL`，并注释掉 `src/constants/product.ts` 中的 `PRODUCT_URL` 常量。

MCP 规范中 `websiteUrl` 是可选字段，删除不影响连接、工具调用或协议合规性。
