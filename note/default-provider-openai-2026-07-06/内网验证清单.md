## B. 内网真机 —— 核心行为验证（最关键）

> 目标：验证"默认永不连 `api.anthropic.com`" + 逃生舱可用 + 向后兼容。

| # | 场景 | 预期行为 | 结果 |
|---|------|---------|------|
| 1 | **完全不设任何 `YWCODER_USE_*`**，配好网关 `OPENAI_BASE_URL` / `OPENAI_API_KEY` | 正常走内网网关；**绝不产生对 `api.anthropic.com` 的出站请求** | [ ] |
| 2 | 不设 env，**故意不配** `OPENAI_API_KEY` / `OPENAI_BASE_URL` | 启动时**快速报错退出**，而非卡住 / 超时（不尝试连不可达的 Anthropic 后 hang） | [ ] |
| 3 | `YWCODER_USE_ANTHROPIC=1` | 走 Anthropic 直连（内网连不上属正常，关键是确认它**确实在尝试 Anthropic**，说明逃生舱生效） | [ ] |
| 4 | `--provider anthropic` | 同 #3；且已保存的 openai profile **不覆盖**此选择 | [ ] |
| 5 | 老用户旧变量 `CLAUDE_CODE_USE_OPENAI=1` | 行为不变，正常走网关（向后兼容） | [ ] |
| 6 | 默认 + 未设 `OPENAI_MODEL` | 默认模型 `gpt-4o` 发到网关 —— **确认网关接受此模型名**；不接受则需设 `OPENAI_MODEL` | [ ] |
| 7 | `YWCODER_USE_OPENAI=1`（显式设） | 行为与改动前一致，正常走 OpenAI | [ ] |
| 8 | 默认 + codex base URL / codex 模型 | `getAPIProvider()` → `codex`，走 codex 传输（与显式 `USE_OPENAI=1` 一致） | [ ] |
| 9 | `/provider` 命令 & 启动屏（默认无 env） | 显示 **OpenAI-compatible**，**不是 Anthropic**（验 #13/#14 展示层） | [ ] |
| 10 | 在 `/provider` UI 里从 Anthropic profile 切到 openai/github profile | 切换生效，不残留 `USE_ANTHROPIC` 把 provider 盖回 firstParty（验 #15） | [ ] |
| 11 | swarm / tmux 子进程（若使用） | `YWCODER_USE_ANTHROPIC` 正确转发到子进程 | [ ] |
| 12 | grpc / headless 模式（若使用 `dev:grpc`） | 默认同样走 openai，不回退 Anthropic（验多入口覆盖） | [ ] |

### 场景 1 / 2 的验证技巧

- 抓包（或代理日志）确认默认路径**没有任何**对 `api.anthropic.com` 的出站连接。
- 或临时把 `ANTHROPIC_BASE_URL` 指向一个必然失败的地址：只要默认路径不因此报错，就说明根本没走 Anthropic。

## D. 发布说明要点（供对外公告参考）

1. **默认 provider 已改为 OpenAI**：不再需要设 `YWCODER_USE_OPENAI=1`。如需切回 Anthropic，用 `--provider anthropic` 或设 `YWCODER_USE_ANTHROPIC=1`。
2. **默认模型 `gpt-4o`**：确认内网网关接受，否则设 `OPENAI_MODEL`。
3. **启动需 OpenAI 凭证**：须配置 `OPENAI_API_KEY` + `OPENAI_BASE_URL`（本地 Ollama 模式可为本地地址），否则报错退出。
4. **老用户迁移**：原依赖 Anthropic keychain/OAuth 的用户，升级后需显式 `--provider anthropic` / `YWCODER_USE_ANTHROPIC=1`，或改配 OpenAI 网关凭证。
5. **自动更新已阻止**：3P 模式不检查上游更新，手动 `git pull && bun run build`。
